## 数学正确性

执行 `npm test`，38 项测试全部通过。检查内容包括：

- 30 关均有且仅有一个解，解中的数字和全部约束均合法。
- 独立全排列枚举再次验证唯一性；该枚举不调用生产求解器及其剪枝，也不复用引擎的算术实现。
- 基准关第 4 关保持行和 15 / 13 / 17、列积 72 / 144 / 35、主对角线和 12。
- 重复数字、非法数字、额外数字、固定格无解状态和不完整棋盘得到正确处理。
- 提示能够识别尚未填满、但剩余数字已无法满足的局部条件，不引导玩家填入不存在的数字卡。

测试源文件见 [engine.test.mjs](../tests/engine.test.mjs)。

## 难度分档依据

[难度评估脚本](../scripts/analyze-difficulty.mjs) 使用独立的候选传播模型，反复应用三类规则：单条线索的可行组合过滤、已使用数字的排除，以及数字只剩一个可放位置时的确定。停止传播后，再以固定的选格和数字顺序分析假设分支。

| 关卡 | 基础传播后确定格 | 剩余候选总数 | 首次找到解的假设层数 |
|---|---:|---:|---:|
| 普通基准关 4 | 3 | 15 | 1 |
| 挑战关 25 | 0 | 52 | 2 |
| 挑战关 26 | 0 | 37 | 2 |
| 挑战关 28 | 0 | 57 | 2 |

“剩余候选总数”是每格候选数量之和，已确定格计为 1。3 个教学关均能在该模型下直接推导完成；9 个挑战关在基础传播后均未解完，保留 33～76 个候选，需要进一步组合条件。

这些指标说明挑战关需要超出本模型基础规则的推理，避免仅以线索条数分档。假设层数依赖所用算法和搜索顺序，既不是学生必须猜测的次数，也不代表实际感知难度。面向学生的试玩校准仍未完成。

复现命令：

```sh
node scripts/analyze-difficulty.mjs
```

## 浏览器界面与交互

记录使用 Chrome 156 的隔离无头浏览器上下文，通过合成触摸事件测试交互。测试视口为 360×800 和 320×800，并在窄屏场景把计算后的字体尺寸放大至 130%。该字号检查是浏览器内模拟，不是 Android 系统字体或 WebView 缩放实测。

21 项交互检查覆盖点选填数、拖放后立即继续操作、数字移动与交换、撤销、候选标记、擦除、提示、冲突高亮、重置确认、帮助弹窗、Android 返回回调、各难度通关、下一关、末关边界、存档恢复、损坏存档和存储不可写。

8 个布局快照中，横向溢出和小于约 44 CSS 像素的按钮均为 0；运行时错误与失败资源请求均为 0。另记录了 4 种触摸会话组合，以及键盘触发按钮的检查结果。这些结果仅覆盖测试脚本所检查的页面和操作，不构成完整无障碍认证。

测试源文件见 [ui-smoke.mjs](../tests/ui-smoke.mjs)，公开结果见 [ui-report.json](validation/ui-report.json)。执行该测试需要本机安装 Chrome 或 Edge，或通过 `CHROME_PATH` 指定兼容的浏览器程序。

```sh

npm run test:ui
```

脚本以 Chromium 61 为语法编译目标，界面为较旧 WebView 配置了棋盘比例与视口高度等 CSS 回退。这是兼容性设计，不是 Android 8.0 或旧 WebView 已通过实测的证明。构建步骤见 [BUILDING.md](../BUILDING.md)。
